01 / The decision

Stop making stored connections the center of the product.

Today the database reflects how the backend discovers information: connections, DNS, attribution, grouping, associations, capture chunks and several kinds of route state. The map then reconstructs a useful view from those pieces. Persist the time-based facts the map needs, and move that reconstruction into one backend projection.

Observe & classifyPacket counters, bounded DNS cache and transient connection identity. No retained payload content.
→
Persist compact traffic50 ms samples in five-second chunks, grouped by client, service and destination binding.
→
Serve map windowsActivity blocks, directional volume, location, capture quality and valid route evidence.

Delete duplicated state

Remove the durable flow → attribution → episode → association chain from normal operation. Source ports, socket states and raw DNS history become diagnostic details.

Add the missing concept

A service identity such as svt.se can have many activity blocks. The current activity_episodes are permanent groups within a session; idle gaps never split them.

Keep the useful precision

Retain fine traffic timing, directional bytes, unknown destinations, capture gaps and historical route validity. Collection reduction should not erase the map’s evidence.

The real tradeoff: bounded provenance. Core mode will not retain enough raw connection history to reattribute every old byte later. Classification can change in a short provisional tail; after sealing, it is frozen. This deliberate limit removes a large part of the current persistence and reconciliation machinery.

Why seven? Keeping stored flows would offer a lower-risk eight-collection consolidation, but retain the main flow lifecycle and joins. Combining everything into one session JSON document would hide the same complexity inside larger updates. Seven gives each durable record one clear purpose.

03 / The new product concept

“SVT activity over two minutes.”

Use a site activity block as the stored concept. The gateway can observe network activity associated with a service; it cannot see the foreground tab, distinguish quiet reading from absence, or prove that a person browsed for the whole interval.

45 seconds

Starting default: 45 seconds, then calibrate against consented browsing recordings. This is a heuristic, not a measured browser session boundary. The closing grace period never adds to the reported span.

  1. Identify the client and supported service.

    Use a session-scoped device/lease identity where available; an IP address alone is not a person or a durable device identity. Apply the existing registered-domain and explicit-alias rules. Shared IPs, timing and provider names do not establish a shared website. Keep ambiguous or hidden traffic independent, keyed by endpoint.

  2. Start from actual captured activity.

    Payload-bearing 50 ms buckets seed a block for the same client and service. Union concurrent bucket intervals to calculate active time. TCP ACK-only bytes remain in map totals but cannot extend a block. Encrypted control traffic and keepalives can still look like activity; this heuristic cannot infer attention.

  3. Join nearby intervals, with coverage as evidence.

    Join when the observed quiet gap is at most the configured threshold. A longer confirmed quiet gap creates another block. A capture interruption creates an explicitly uncertain boundary, not proof of a new visit. Partial capture gives the block partial quality.

  4. Allocate time slices, never entire connections.

    One long-lived connection may contribute to several blocks; many connections may contribute to one. Assign bytes by half-open bucket intervals. Control-only bytes outside block intervals remain in an “other traffic” total. Concurrent services may overlap, and their durations must not be added as human browsing time.

  5. Keep a small provisional tail, then seal it.

    Start with a ten-second attribution correction horizon. While transient per-connection contributions still exist, move bytes between service aggregates atomically and recompute affected blocks. Close a block only after the quiet-gap deadline and persistence watermark pass; its end is still the last active bucket. Late attribution after sealing does not rewrite old aggregates.

Two identities, two meanings. service_key = svt.se is stable grouping. block_id identifies one temporal activity interval. Never put one block ID on a connection. Stable blocks keep their IDs as retention clips their visible start; provisional splits and merges may replace IDs through a session revision.

If exact navigation, foreground time or dwell time becomes a requirement, add an explicit browser-side signal as a separate product feature. Passive metadata alone cannot supply it. The accepted core remains useful without that signal.

04 / The accepted durable model

Seven collections with seven clear jobs.

Store bounded numeric samples and the evidence needed to interpret them. JSON is appropriate for a fixed-size sample array or hop list; it should not hide unbounded lists of flows, memberships, jobs and caches inside one record.

Aggregate across connections only when these dimensions agree. This preserves different services sharing a CDN IP and different route bindings on one IP. An unknown endpoint remains separate from a confidently named service. Confidence is conservative when evidence is mixed; a bounded example list is not presented as complete raw provenance.

One byte authority: captured wire bytes include headers and retransmissions. Do not add conntrack lifetime counters to them. Conntrack helps transient identity and diagnostics; capture gaps stay gaps in core mode. No inferred waveform fills missing data.

Persist promptly; classify briefly

Keep the current roughly 400 ms flush cadence as an initial target. Provisional aggregates are durable before their classification is final. A bounded RAM contribution ledger supports corrections during the ten-second tail; an atomic transaction subtracts and adds exactly the same bytes.

On restart, seal the persisted tail with its existing labels, start a new capture epoch, and mark any unacknowledged interval unknown. Rebuild open blocks from persisted chunks. Fresh snapshots must never overwrite earlier samples from the same five-second wall-clock interval.

Capture first; enrich afterward

Keep packets that conntrack polling never sees. A provisional tuple can be classified or stay unknown without waiting for a durable flow record. Bound DNS, tuple and contribution caches by time and capacity; an eviction loses a label opportunity, not captured traffic.

Use connection generations where observable: connection ID, teardown, disappearance or counter reset. Reuse between polls may remain ambiguous. After reuse, eviction or restart, prefer unknown over carrying a stale hostname forward.

Historical labels become explicit snapshots. Unlike an event archive, the sealed core cannot reconstruct every past DNS decision or globally reclassify old connections. Contradictory evidence can retract provisional labels; after sealing it affects new traffic. Pin policy for the session and apply alias changes to new sessions. An opt-in raw recording may support a separate, deliberate reprocessing workflow.
05 / Simplify the most stateful subsystem

Two route records: what we attempted, and what the map knew.

The current route subsystem has six collection families. Replace them with probe_runs for durable admission and route_evidence for playback. Simplify the policy at the same time, so six lifecycles do not reappear inside a generic state document.

Keep the safety and evidence

  • One paced worker, finite per-session and network/family budgets, bounded path storage, and cooldown after repeated failures.
  • Charge each method attempt before launching it. A crash or cancellation does not refund the charge. Queries use a stable network fingerprint, not a restart-created capture epoch.
  • Use a deterministic hourly admission scope for continuous sessions, and lifetime scope for an open recorded session. Preserve manual-attempt limits.
  • Bind evidence to IP, protocol, destination port and session network epoch. An unknown network identity uses a conservative quota scope, not a fresh allowance.
  • Keep measured time separate from available time. Select the latest applicable publication, then check expiry/invalidation; never resurrect an older path after newer invalidation.

Delete or reduce the extra behavior

  • No cross-session persistent cache. Reuse a valid path only within the same session and network epoch, without refreshing its measurement age.
  • Publish terminal useful paths. Drop persistent progress and confirmation histories. A path may appear later, once the bounded probe completes.
  • Bound enrichment. Keep the path self-contained. At most one useful enrichment revision per run; no separate event reconciliation layer.
  • Derive current status. Latest attempt outcomes and ledger counts supply the admin summary. No separate outcome, budget or cache collection.
  • Detailed probe bundles are optional fields. Bound their size and retention within diagnostic mode; path hops and essential quality remain core.

Retain the current defaults as the initial ceiling: 20 automatic targets, 40 automatic attempts, 40 network/family attempts per rolling hour, 10 manual attempts, 100 path snapshots and a 16 MiB evidence cap. Within each admission scope, allow at most one automatic attempt per selected method (at most two methods) for a binding, and stop on useful evidence. Preserve the 30-minute pause after five distinct completed comparisons without useful gain; five individual attempt rows are not five comparisons. Removing budget-reset or “extra allowance” controls is a deliberate simplification; manual work still consumes an explicit allowance. Validate the exact policy against existing route contract tests before replacing the coordinator.

Visible consequence: a new session may initially show destination points without route paths, and may be unable to probe immediately if earlier sessions exhausted the network budget. Deleting a session must not delete those recent charges. Keep admission records through the longest quota/cooldown horizon; keep all attempts needed for an open recorded session’s lifetime budget.

A path and a network_invalidated record are two explicit variants of map evidence, with validated fields. They are not arbitrary key/value events or fake empty traceroutes. Network invalidation remains a historical fact even if no path was currently visible. Routing evidence ↓

06 / Fewer joins, fewer moving parts

Give the browser a map window.

The browser should own playback, camera movement, filtering and rendering. Go should own attribution, grouping and the rules for selecting historical evidence. Keep the existing Go/PocketBase stack and a single process.

GET /api/sessions/:id/manifest
  → lifecycle, retention, clock, policy, capture health, revision

GET /api/sessions/:id/map?from=…&to=…&resolution=…
  → block segments + traffic series + capture coverage
    + referenced destinations + route-evidence revisions

GET /api/sessions/:id/blocks?from=…&to=…&cursor=…
  → paged activity summaries for the retained interval

GET /api/sessions/:id/diagnostics/…   // only when enabled
  → raw connection / DNS / detailed probe information

Use bounded aligned windows, a response-size cap and versioned replacement semantics. A response carries the session revision, covered interval and completeness; a revision mismatch or retention advance causes a refetch. One coalesced session revision signal replaces collection-by-collection subscriptions. Compute coarse display resolutions from the same samples, cache bounded windows in memory, and keep fine samples available on demand.

A playback window includes the route revisions that become available inside it plus the necessary pre-window anchor and invalidation state. It must not apply the latest route to the whole window. Clients can play cached windows locally; this is not a request per animation frame.

07 / Every collection accounted for

The “22 collections” count needs one correction.

Read-only inspection of this checkout’s local database found 19 current application collections + two legacy collections + the users auth collection. That explains 22 visible collections. Five PocketBase system/auth collections bring the registered total to 27; those are separate from this product redesign.

The honest target is 19 → 7 core application collections, a 63% reduction in collection count, or ten with all three diagnostic collections installed. This is not a claim of 63% less disk use or code. A fresh core installation would show eight non-system collections if users remains. Optional means optional storage

The full diagnostic profile adds flow_diagnostics, dns_queries and gate_events, each with a time and byte cap. Detailed probe fields live on bounded attempt records. Enabling it is a forward-looking capture choice; it cannot recover old raw data.

A core installation should not create these three collections. Turning a diagnostic profile off stops writes; it does not silently delete its existing records or schema. The UI should clearly indicate whether raw diagnostics were recorded.

Start with a clean application schema

Exclude the legacy packets and traceroutes tables from fresh setup. Existing development recordings are disposable; no import, conversion or old-recording reader is needed. Keep the auth schema required by the application.

PocketBase’s five system/auth collections and internal metadata tables remain. Remove _domain_catalogue_checkpoints only together with the retired catalogue feature. A hidden custom table still counts as complexity.

08 / Make storage genuinely smaller

Reduce write amplification, then measure.

The useful reduction comes from aggregating compatible connections, removing duplicate derivation writes and retaining only deliberate evidence. Fewer collection names alone say little about storage cost.

Illustrative sizing, not a benchmark. Two minutes of continuous activity produce about 24 five-second rows per active dimension set. Thirty simultaneously active flows across three compatible service/destination bindings would produce roughly 720 current flow chunks versus 72 aggregate chunks, before other records. Real savings depend on concurrency, alignment, sparsity, attribution, protocol/port diversity and epoch changes; in the worst case, every flow has a distinct binding and aggregation saves little.

09 / Implementation sequence

Adopt the new model and rewrite directly.

The seven-collection architecture is the new standard. Start with fresh application data and replace the existing implementation. These steps are a working order, not separate releases or approval gates.

Working checklist: implementation-plan.md contains the checkable tasks. Existing development recordings are disposable. Git provides the fallback for code; an older version can run against a fresh database for that version. There is no migration, legacy playback, dual writing or shadow mode to build.
01

Establish the new schema and vocabulary

Record the accepted architecture in the domain documentation and a storage ADR. Replace the application migration history with a clean seven-collection schema, define the new types and provide one development reset/bootstrap path. Use the new model as the basis for every subsequent change.

02

Rewrite capture, aggregation and blocks

Persist aggregate traffic directly from capture, with bounded in-memory classification and independent capture coverage. Implement the provisional tail, crash-safe flushes, temporal block projection and rolling retention. Keep useful capture code; remove the durable flow/attribution/association chain.

03

Simplify routing around admissions and evidence

Use transactional probe reservations and self-contained terminal path publications. Preserve quotas, historical invalidation and replay semantics. Remove the persistent cross-session cache, duplicated observations and confirmation/progress machinery. Reuse the existing probe engine and supported method rules.

04

Replace the API and frontend data path

Build the manifest, bounded map windows, activity-block endpoints and one revision signal. Move both dashboards to the new contract, keep playback local and add activity-block browsing. Delete the old collector joins and transport bookkeeping as their replacements are built.

05

Finish diagnostics and remove obsolete code

Make raw flow/DNS history and gate audit an explicit diagnostic profile with bounded storage. Preserve the gate’s fail-open and audit requirements. Delete obsolete collections, catalogue checkpoints, compatibility paths, configuration and tests. Update scripts, fixtures and guides to the new standard.

06

Verify the new implementation

Use focused fixtures and a fresh database to check accounting, grouping, capture gaps, restart behavior, retention and route limits. Run the relevant tests and builds, check both dashboards in a browser, and smoke-test representative traffic on the gateway. Completion means one working data path, seven core collections and three optional diagnostic collections.

Correctness checks for the new model
  • Conservation: every durably persisted sample contributes its wire bytes exactly once; named blocks plus independent/control traffic reconcile. Capture, queue and pre-flush crash losses produce incomplete coverage. Seeking and clipping exclude future and expired bytes.
  • Identity and time: shared-IP services stay separate; tuple/lease reuse cannot inherit stale labels; one continuing connection can form two blocks; concurrent activity contributes a union of active intervals.
  • Durability: duplicate/stale flushes and restart cannot overwrite or double-count chunks. Coverage stops at the acknowledged watermark, and retained block anchors survive restart.
  • Inference: uncertain traffic stays independent; provisional reassignment is atomic; sealed labels retain the session’s policy.
  • Routes: expiry, availability, invalidation and pre-window anchors remain correct in replay. Restart or session deletion cannot reset spent allowances.
  • Bounds and behavior: long-running capture, high binding cardinality and optional diagnostics remain bounded. Forwarding continues when route discovery or diagnostics are unavailable.
