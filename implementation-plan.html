02 / Product rules

Three invariants guide the build

TRUTHFULNESS

Observed is not derived

Measured packet/flow events, inferred relationships, and cosmetically interpolated movement stay visibly distinct.

DETERMINISM

Cursor in, frame out

No animation owns hidden local time. Remotion renders every token from event timestamps and the shared session cursor.

SAFETY

Passive unless explicit

Normal gateway mode remains untouched. Traffic gating requires a lab flag, an allowlisted client, and an operator-visible armed state.

03 / Architecture

Keep high-volume traces out of the normal session store

The existing shared runtime remains the authority for sessions, time, window loading, and live-edge behaviour. The experiment adds a bounded trace channel and debug-only state.

Recorded path

session window→trace adapter→temporal index→Remotion scene

Existing flow, DNS, activity, attribution, destination, and route records are normalized into pipeline events. Missing historical processing times are labelled as derived timing.

Live observe path

observers→debug event hub→SSE stream→ring buffer

Fine-grained trace events travel through a separate one-way stream. A small delay behind the live edge absorbs jitter while PocketBase remains the durable source of truth.

Turn-based path

FORWARD / NEW→NFQUEUE 42→gate controller→operator decision→temporary allow set→verdict

The controller copies only enough header data to classify and display a packet. The kernel retains the actual packet until a verdict. Once a flow is approved, a short-lived allow entry bypasses further manual decisions for that tuple.

Not one universal queue: forwarded IP traffic can be gated in FORWARD. DNS currently terminates locally and needs its own later gate. ARP, Wi-Fi management, DHCP, NTP, and access to the operator UI must always bypass manual approval.
04 / Event contract

A small append-only vocabulary

Every visual transition and gate decision gets stable identity, source time, causality, and an honest timing provenance.

type PipelineEvent = {
  id: string
  sessionId: string
  traceId: string
  parentId?: string

  kind:
    | 'dns' | 'flow' | 'burst'
    | 'attribution' | 'route' | 'gate'

  stage: PipelineStage
  direction?: 'client_to_remote' | 'remote_to_client'

  occurredAtMs: number
  processedAtMs?: number
  sequence: number

  timing: 'observed' | 'derived'
  summary: HeaderOnlySummary
}

Contract decisions

  • occurredAtMs + sequence is the deterministic sort key.
  • traceId groups DNS, flow admission, activity, and later attribution without pretending every relationship is certain.
  • Existing 50 ms activity buckets create burst tokens; no raw-packet event is persisted.
  • Gate actions use the same event stream: queued, approved, rejected, expired, and bypassed.
  • Payload fields are prohibited in the durable schema.

07 / Safety model

The controller must be easier to escape than to activate

Turn-based networking intentionally creates failure. Guardrails ensure the experiment cannot silently become the gateway’s normal operating condition.

Controller lifecycle

  • Default state is OFF; activation requires the lab environment flag and an operator action.
  • Only explicit client IP/MAC allowlists may enter the gate.
  • Disarm drains outstanding packets, removes queue rules, and invalidates approved-flow entries.
  • The operator API stays on gateway-local INPUT traffic and never enters FORWARD.
OFF→ARMING→ACTIVE→DRAINING→OFF

Backpressure and timeout policy

  • Use NFQUEUE bypass when no userspace listener exists.
  • Enable fail-open behaviour when the kernel queue is full.
  • Start with a maximum of 128 pending flow decisions, below the kernel’s default 1,024-packet queue.
  • Recommended safety auto-release: DNS 2 s, established packets 500 ms, new flow 10 s. Strict mode may override this for one test client.
  • Surface every auto-release and overflow; never make missing queue data look like successful approval.

08 / Acceptance

Definition of done

The same session and cursor always produce the same Remotion frame.
Replay can distinguish observed timestamps from inferred transition timing.
Live mode can scrub backward and return to the delayed live edge without reloading.
A 60-minute, 30-client soak test keeps browser and gateway memory bounded.
Stopping or crashing the gate controller does not strand normal forwarding.
The operator UI remains reachable while all allowlisted external flows are held.
No durable trace or audit record contains packet payload data.
Queue overflow, capture loss, and automatic verdicts are visible and test-covered.
Normal mode produces identical iptables rules and forwarding behaviour to today.
Strict per-packet mode refuses to arm without exactly one client and one flow filter.
09 / Review

Decisions to confirm before implementation

Recommended defaults

The plan assumes the following choices. They are isolated enough to change after the passive replay slice, but confirming them prevents the gate work from drifting.

  1. Manual unit: approve a new flow, not every packet.
  2. Historical honesty: show inferred node transitions, but label them as derived timing.
  3. Live presentation: render roughly 500 ms behind the newest event for smoother movement.
  4. Failure policy: fail open and visibly record the bypass.
  5. First gate scope: forwarded TCP and UDP for explicitly selected clients; DNS comes later.
  6. Strict mode: available only for a single isolated client/flow with an explicit warning.
