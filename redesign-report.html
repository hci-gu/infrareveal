01 / Revised design direction

Different work deserves different interfaces.

Traffic keeps its large timeline. Lab returns to the flow between gateway nodes. Sessions adopts the same quiet slate surfaces as Traffic, with more space and softer controls.

Traffic / Inspect time

A clearer timeline workspace

The timeline takes the largest share of the working area. One playback bar combines Play, the current position, a full-session scrubber, five-second steps, playback speed, visible window and return to live.

Whole-second clocks, shorter clip labels and a single 36px track height reduce noise while retaining endpoint, direction, evidence and capture quality. The event dock and inspector remain resizable.

Lab / Follow the path

A dedicated node canvas

A broad forwarding path runs from client through ingress, connection tracking, the flow gate, forwarding and NAT to the remote endpoint. DNS and passive observation branches explain where the evidence comes from.

Trace selection, node inspection and step-through controls belong to this graph. Current approvals stay beside it. Lab has its own layout, controls and visual language.

Sessions / Choose a source

A modern desktop library

A source list, restrained category navigation and selected-session details replace the large active-session hero. Aligned rows make recordings easy to scan; clear launch actions open Traffic or Lab.

Slate panels, subtle separators, softer corners and more generous spacing tie Sessions to Traffic. Tool selection happens here; neither application contains a switch to the other.

Make scope part of the metric

Track counters are per-flow totals. Window measurements use activity bins inside the visible interval. Loaded scope and capture resolution belong in the evidence details. Session totals remain in Sessions; partial loading is explicit.

Express uncertainty honestly

“No observed traffic” requires complete coverage. Unloaded and incomplete intervals use different hatch treatments and text. Low confidence is distinct from missing evidence; a capture failure cannot become a zero-byte reading.

Stay within observable metadata

No HTTP request counts, URLs, response codes, decrypted contents, application response times, or inferred app usage presented as fact. UDP/443 remains UDP/443 unless separate evidence supports a more specific protocol label.

04 / Implementation plan

Build each tool around its own working surface.

Retain the existing routes and shared session contracts. Share data access and visual tokens where useful; keep Traffic and Lab as independent UI implementations.

01 / SESSIONS + STYLE

Establish the source browser

Introduce the slate palette, typography, restrained borders and softer controls used by Sessions and Traffic. Rework the session list into categories, aligned records and selected-source details with two explicit launch actions.

Keep live/recorded identity, manifest completeness, existing deep links and on-demand summaries.

Review: a source opens the correct tool and mode. Sessions feels cohesive with Traffic without inheriting its working density.

02 / TRAFFIC

Clarify playback and preserve scale

Use a viewport-filling timeline with a single 36px track density. Combine the navigator and transport into one bottom bar. Add an obvious scrub handle, whole-second clocks, five-second steps, zoom window and explicit return to live.

Retain synchronized labels, ruler, capture gaps, group folding and linked evidence panes. Use actual activity bins at the loaded resolution.

Review: repeated seeks and live → past → live preserve the chosen time, selection and capture-gap meaning. The timeline remains the dominant pane.

03 / LAB

Restore the node-flow focus

Build a separate graph layout from the existing Proxy Lab path. Add trace selection, inspectable nodes, optional evidence branches, pan/zoom and fit-to-path. Surface selected-node facts beside the graph.

Keep current queue, gate modes, target clients and control health distinct from historical trace inspection. Preserve authorization and decision lifecycle behavior.

Review: a connection can be followed through the relevant nodes. Historical replay cannot make an expired or recorded decision actionable.

04 / DATA + VERIFICATION

Connect the evidence

Connect existing flow, DNS, attribution, association, destination, route and gate records to the correct tool. Retain overview/detail loading, range caches and raw timestamps. Label lifetime totals and window measurements separately.

Verify dense sessions, disconnected gateways, incomplete capture, missing enrichment, recorded audits, keyboard navigation and large-screen layouts.

Review: displayed facts resolve to source evidence; missing data stays explicit; neither tool inherits the other’s navigation or layout.

Reuse the data foundation

The session store, range controller, flow/activity projections, scene window selector, quality projection, and gate/trace clients remain useful across separate interfaces.

Give Traffic the real viewport

The current composition is 1440 × 810 with large fixed headers. Make the interactive track surface adapt to pane geometry and virtualize large record sets. Reuse selectors with the existing Remotion export path while keeping export dimensions independent.

Verify each work pattern

Check scrubber/ruler agreement, live following, linked selection, whole-second formatting and pane resizing in Traffic. Check graph focus, branch meaning, node inspection and current-queue isolation in Lab. Check source selection and launches in Sessions.

Desktop is the design target: review at 1280 × 800, 1440 × 900 and larger. At smaller widths, collapse optional Traffic panes and allow timeline scrolling; Lab needs a movable graph viewport. The report keeps the sketches’ desktop geometry inside horizontal scroll containers on phones. Real session details load during implementation.

Implementation / 07 Sep 2026

Study 03 in the application.

The sketches remain illustrative design references. Follow the implementation checklist and browser validation procedure for implementation context and ongoing checks.

Traffic uses observed coverage

The navigator shows time, capture coverage and the visible window because a complete activity overview is not always available. Tracks and the event ledger are virtualized. During playback the window advances in five-second steps while the playhead moves; manual seeking and zoom retain the exact inspection cursor.

Lab preserves the complete gateway

The implementation retains inbound traffic, local DNS gating and drop paths, alongside passive observation branches. A source-event selector distinguishes a held event from its later verdict. Replay controls and authenticated flow, strict and DNS setup stay subordinate to the graph; the queue remains NOW.

Small windows remain usable

Optional panes close initially on smaller screens. Traffic keeps explicit playback controls and Lab keeps a pannable canvas with readable nodes. Sessions becomes a vertically arranged list and source-details view. Source metadata, raw precision and the controlled client remain accessible.
