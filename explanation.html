Inside the gateway pipeline

What physically happens to a packet, what InfraReveal merely observes, and what is inferred later. The crucial idea: the diagram combines three different kinds of work on one canvas.

The short answer about the confusing three

DNS attribution guesses which observed DNS name best explains a flow. GeoIP + reverse DNS adds facts about the destination IP. Traceroute runs a separate route probe. None of them is inline with the participant’s connection.

01 · Mental model

One picture, three planes

A line between boxes can mean “the packet actually travels here,” “metadata was observed here,” or “a later result was written here.” Reading every line as physical packet movement is the source of most confusion.

This is a gateway observer, not the old transparent HTTP proxy.

The current entrypoint explicitly removes the legacy port 80/443 redirect rules. Linux routes and NATs normal traffic without terminating TLS. InfraReveal records bounded network metadata—tuples, counters, DNS answers, timing and coarse packet activity—not whole HTTP requests.

03 · The confusing three

Three workers, three different questions

They all start from flows and eventually write to PocketBase, but they should never be mentally collapsed into one “lookup” step.

DNS attribution

“Which hostname probably led this client to that IP?”

Looks backward in the same client’s DNS history and compares timing plus exact answer IP.

Output: flow_attributions
GeoIP + reverse DNS

“What public context do we know about this IP itself?”

Uses reverse DNS, a local GeoIP database and a small known-network rule.

Output: destinations
Traceroute

“What route does a new probe from the gateway see now?”

Runs a separate numeric traceroute toward one unseen destination socket.

Output: routes
WORKER 01 · INFERENCE

DNS attribution

Runs every 3 seconds for the active session.

Load all flows and dns_queries belonging to the active session.
For each in-scope flow, use start (or last_seen) as its reference time.
Keep DNS answers from the same client whose IP exactly equals the flow destination and is within 5 minutes.
Choose the closest match; on an exact timing tie, prefer the DNS record with more CNAME aliases.
MATCH → MEDIUMStores the queried name, DNS relation, source dns_answer and a human explanation.
NO MATCH → LOWStores destination-only evidence. The hostname remains empty because IP alone is not a hostname.
HIDDEN PORTSUDP/443, 853, 51820, and UDP/500 or 4500 become hidden: encrypted DNS, QUIC or tunnelling may obscure local DNS evidence.

Why not “Local DNS cache”? dnsmasq has resolver/cache behavior, but this node does not: it reads persisted DNS observations and attributes flows to them. The algorithm normally expects DNS before the flow, but permits a DNS timestamp up to 10 seconds after it to tolerate observation ordering. Existing stronger conclusions are not downgraded. In the same 3-second loop, the backend also groups selected first-party site families into 30-second episodes and may associate freshly resolved companion flows within 8 seconds. The graph token visualizes the flow-attribution result, not every activity-association update.

WORKER 02 · ENRICHMENT

GeoIP + reverse DNS

Runs every 3 seconds; refreshes slow lookups after 15 minutes.

Read active-session flows, filter them to the observation scope, and reduce them to unique destination IPs.
Upsert the globally unique destinations.ip record and update first/last-seen bookkeeping.
When stale, run reverse DNS and query the local MaxMind city database for city, country and coordinates.
Derive a provider label from reverse DNS, except known network rules take priority (currently Apple’s 17.0.0.0/8).
IDENTITYOne destination record per IP, shared across sessions; not one per flow and not one per hostname.
LOCATIONGeoIP describes an address-registration estimate. It is not the participant’s location and may be approximate.
CURRENT GAPThe schema contains asn, but this worker does not currently populate it. Organization is only set by explicit known-network logic.

Reverse DNS answers “what name does the owner publish for this IP?” DNS attribution answers “what name did this client resolve before opening the flow?” Those names can differ, especially behind CDNs. This worker never decides which website caused a connection. It also derives a provider label, so the new UI name covers its main lookups but not every small output.

WORKER 03 · ACTIVE PROBE

Traceroute

Runs every 30 seconds and attempts at most one missing route per tick.

Reduce active-session flows to unique IP + protocol + port observations and skip sockets already routed for this session.
For TCP, invoke traceroute -T -p PORT. For other protocols, use the platform traceroute default.
Use numeric output, one probe per hop, 1-second hop waits, at most 20 hops and a 25-second overall process timeout.
Parse hop IPs and timings, mark missing hops, GeoIP-enrich visible hops, then save success, partial result or error.
NOT THE FLOWThis is a new probe emitted by the Raspberry Pi. It does not record the exact route taken by the participant’s earlier packets.
PARTIAL IS NORMALRouters may ignore probes, load-balance, filter traceroute or use asymmetric paths. Asterisks do not mean ordinary traffic failed.
BACKLOGOne new route every 30 seconds means many unique destination sockets can take a long time to cover.

The command uses -n, so hop hostnames are not currently filled even though the JSON hop type has a hostname field. Also, started_at and completed_at are currently written to the same post-command time; they do not measure traceroute duration.

06 · Storage & replay

How live and recorded become the same movie

The animation is a projection of timestamped facts. Live mode keeps adding facts near the moving edge; recorded mode reads a fixed range. Remotion receives the same deterministic scene for a chosen cursor time.

01 · OBSERVE

Timestamp facts

DNS, flow, burst and gate events get occurrence times; capture completeness is recorded per time window.

02 · PERSIST

PocketBase records

Durable collections keep the full session; the debug trace ring is only short-lived.

03 · WINDOW

Fetch nearby time

The session API pages bounded ranges instead of loading an hour into memory.

04 · INDEX

Zustand + temporal index

Shared state normalizes entities and locates only records relevant to the cursor.

05 · PROJECT

Render the scene

UI and Remotion convert events around cursorMs into nodes and moving tokens.

There are two useful timestamps

  • occurredAtMs: when the network fact is understood to have happened. This drives playback.
  • processedAtMs: when an observer or worker emitted/created the trace fact. This reveals observer lag.
  • Derived conclusions intentionally keep the flow/destination reference time where possible, even when computed later.

Live trace versus session history

  • The optional SSE debug trace is bounded: 20,000 events and 30 seconds retention by default, batched every 50 ms.
  • PocketBase collections are durable and feed the session manifest/window API for replay.
  • Detailed window requests are capped at 15 minutes and page 500 records by default (1,000 maximum); the client moves the window with the cursor.
Activity data quality is a timeline property, not a pipeline step.

The debug UI keeps it beside the player: amber or red timeline ranges come from durable flow_activity_windows and mean capture was partial or unavailable. Violet ticks mean the browser missed live SSE trace events. Those are deliberately separate—a live-stream gap can make the animation briefly stale even when the gateway’s durable packet-activity capture is complete.

07 · Timing & limitations

What can wait, what can drop, what cannot be claimed

The observation design is deliberately lossy under pressure; the forwarding design is deliberately fail-open. Quality metadata tells the UI when fine-grained activity is incomplete.

ComponentDefaultMeaning
conntrack sampler2 sPoll interval; flow start is discovery time, not necessarily the first SYN.
DNS attribution / GeoIP + reverse DNS3 sBackground scan cadence for the active session.
Traceroute30 sOne missing destination route attempted per tick.
flow gate watchdog10 sNew-flow decision deadline; expiry accepts traffic because fail-open is required.
strict packet watchdog500 msPer-packet hold deadline in strict mode.
DNS gate watchdog2 sDNS decision deadline; long waits can still trigger client resolver retry behavior.
traceroute process25 sOverall worker timeout; it is unrelated to the participant’s socket timeout.
activity buckets / chunks50 ms / 5 sFine-grained counts are aggregated into persistence-sized chunks.

Inference boundaries

A DNS match is evidence, not proof of user intent. A reverse-DNS name is infrastructure naming, not necessarily the visited site. GeoIP is approximate. Traceroute is a separate point-in-time probe. Packet activity represents countable headers and lengths, not readable application content.

When capture queues fill, metadata is dropped and the affected time windows are marked incomplete. When the lab gate queue/listener fails, --queue-bypass, overflow handling and watchdogs release traffic. Those are different failure policies on purpose.
